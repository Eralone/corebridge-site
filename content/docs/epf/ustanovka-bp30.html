Важно. БП 3.0 — учётная, а не торговая конфигурация. Часть механик платформы в ней недоступна или работает ограниченно. Прочитайте §5 до покупки и настройки.

1. Что нужно до начала

  1. Аккаунт на corebridge.ru с активной лицензией.
  2. JWT-токен из Личного кабинета — как его получить.
  3. Права администратора в 1С.
  4. Открытый исходящий HTTPS до api.corebridge.ru:443.

2. Получение файла

Тот же путь по шагам, со скриншотами каждого экрана кабинета: Первичная настройка.

  1. Личный кабинет на corebridge.ru → «Файл .epf и JWT-токен».
  2. Конфигурация — 1С:БП 3.0.
  3. Скопируйте JWT-токен.
  4. Скачайте unified_bp.epf.

3. Установка

Вариант А — через «Дополнительные отчёты и обработки» (рекомендуется)

  1. Администрирование → Печатные формы, отчёты и обработки → Дополнительные отчёты и обработки.
  2. Добавить из файла… → Продолжить → unified_bp.epf.
  3. Укажите раздел размещения (например Продажи или Администрирование).
  4. Записать и закрыть.

Вариант Б — открыть файл напрямую

Файл → Открыть → unified_bp.epf.

4. Первый запуск

Откроется вкладка CoreBridge. Каталог проектов → «+ Добавить интеграцию».

Полный разбор шагов — Мастер подключения.

5. Ограничения БП 3.0 — прочитайте до настройки

5.1. Что НЕ работает

МеханикаСтатус в БП 3.0
Резервирование запасов⛔ Не поддерживается. Механика недоступна
Аналитика: набор данных «Остатки»⛔ Недоступен. Остальные наборы (продажи, заказы МП, оплаты) работают
Вывод из оборота «Честный знак»⛔ Соответствующие документы не создаются

5.2. Что работает иначе

ЧтоКак в БП 3.0
Складской учёт⚠️ Ограниченный. Отдельного складского справочника с полной аналитикой нет
Остатки товаровЧитаются из бухгалтерского учёта по счёту товаров. Без разбивки по складам — выгружается общий остаток
ЗаказыВместо заказа клиента создаётся счёт на оплату
ОплатаВместо кассовых ордеров — поступление на расчётный счёт и списание с расчётного счёта
ОтгрузкаСоздаётся реализация товаров и услуг
Триггер отгрузкиСрабатывает на проведение счёта на оплату
Маркировка «Честный знак»Базовая поддержка: коды передаются, документы вывода из оборота не создаются
Финансовые отчёты МПТолько базовая схема отражения
ВозвратыПоддерживаются ограниченно
Организация в документахНе обязательна

5.3. Для чего БП 3.0 подходит хорошо

  • Приём заказов с маркетплейсов и сайтов в виде счетов на оплату.
  • Отражение оплат по банку (эквайринг, СБП, платёжные шлюзы).
  • Отражение финансовых отчётов маркетплейсов.
  • CRM-интеграции: контрагенты, сделки, счета, статусы.
  • Уведомления и аналитические выгрузки (кроме остатков).

5.4. Для чего не подходит

  • Складская логистика FBS с точной выгрузкой остатков по складам.
  • Резервирование под заказы маркетплейса.
  • Полный цикл маркировки с выводом из оборота.

Если нужны эти сценарии — используйте УТ 11, УНФ или КА 2 / ERP.

6. Автообновление модуля

Раз в сутки модуль проверяет наличие новой версии unified_bp.epf на сервере платформы и предлагает обновиться из интерфейса 1С.

7. Диагностика

СимптомЧто проверить
Механики «Резервы» нет на Шаге 3ВОжидаемо: в БП 3.0 не поддерживается
В аналитике набор «Остатки» помечен как недоступныйОжидаемо: в БП 3.0 набор stock не выгружается
Остатки выгружаются без разбивки по складамОжидаемо: остаток читается из бухучёта, складской детализации нет
Вместо заказа создан счёт на оплатуОжидаемо: это штатное поведение БП 3.0
Оплата не создала кассовый ордерОжидаемо: в БП создаётся банковский документ, а не кассовый
На Шаге 1 статус подключения пустойДоступность api.corebridge.ru:443, прокси/файрвол, срок действия JWT
Пустая таблица в рабочем местеНажать «Обновить» на самой форме
