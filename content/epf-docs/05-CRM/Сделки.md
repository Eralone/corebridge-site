# Как настроить синхронизацию сделок CRM

Механика переносит сделки CRM в 1С: по каждой сделке создаётся документ заказа. Опрос идёт по расписанию.

---

## Шаг 1. Настроить

Рабочий стол проекта → строка **«Сделки CRM»** → **⚙ Настройка**.

![Настройка CRM: сделки](../images/crm-deals-setup.png)

Здесь задаётся, какие сделки забирать и какой документ по ним создавать. Проверьте соединение кнопкой на форме и нажмите **«Сохранить»**.

---

## Шаг 2. Рабочее место «Сделки CRM»

Рабочий стол → строка **«Сделки CRM»** → **▶ Рабочее место**.

![Рабочее место сделок CRM](../images/crm-deals-workplace.png)

### Верхняя панель

| Элемент | Назначение |
|---|---|
| **Интеграция** | ID проекта (например `CRM_001`) |
| **Статус цикла** | Результат последнего обмена, например `HTTP 200 · принято 4 · приземлено 4` |
| **Следующий опрос** | Время следующего запуска по расписанию |
| **🔄 Синхронизировать сейчас** | Запустить обмен немедленно |
| **📋 Открыть деталь** | Карточка выбранной сделки |
| **✉ Повторить ACK** | Повторно подтвердить обработку события |
| **Показать** | Фильтр (`all` и др.) |
| **Период** | Фильтр по дате (`today` и др.) |
| **↺ Обновить таблицу** | Перечитать таблицу |

**Строка «Статус цикла» — главный индикатор.** `принято N · приземлено N` означает, что все полученные события успешно превратились в документы. Если «приземлено» меньше «принято» — часть сделок не обработалась, смотрите колонку «Статус синхр.».

### Таблица

| Колонка | Значение |
|---|---|
| **ID события** | Идентификатор события платформы |
| **#** | Порядковый номер |
| **ID сделки CRM** | Идентификатор сделки в CRM |
| **Название сделки** | Заголовок сделки |
| **Стадия CRM** | `new`, `processing`, `delivered`, `cancelled` |
| **Документ 1С** | Ссылка на созданный документ |
| **Статус синхр.** | `✓ OK` или ошибка |
| **Обновлено** | Время обработки |

**Итоги внизу:** Итого, Успешно, Ожидают, Ошибки.

Кнопка **«Настройка сделок»** открывает форму настройки.

---

## Какие документы создаются

| Конфигурация | Документ по сделке |
|---|---|
| **УТ 11** | Заказ клиента |
| **УНФ** | Заказ клиента |
| **КА 2 / ERP** | Заказ клиента (организация обязательна, партнёр берётся из контрагента) |
| **БП 3.0** | ⚠️ **Счёт на оплату** — заказа клиента в БП нет |

## Частые проблемы

| Симптом | Решение |
|---|---|
| Таблица пустая | Нажмите **«🔄 Синхронизировать сейчас»**, затем **«↺ Обновить таблицу»**. Проверьте фильтр «Период» — по умолчанию `today` |
| «принято N · приземлено 0» | События приходят, но документы не создаются. Проверьте реквизиты Шага 4 мастера: контрагент, склад, договор; в КА 2 / ERP — организацию |
| В колонке «Статус синхр.» ошибка | Откройте **«📋 Открыть деталь»** — там текст ошибки по конкретной сделке |
| Документ создан не на того контрагента | Настройте поиск дублей и контрагента по умолчанию в [Контрагентах](Контрагенты.md) |
| Событие обработано, но CRM его повторяет | Нажмите **«✉ Повторить ACK»** — подтверждение обработки не дошло до сервера |
| Обмен идёт слишком редко | Уменьшите интервал в настройке |
