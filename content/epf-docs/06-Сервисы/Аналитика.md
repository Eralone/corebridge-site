# Как настроить выгрузку аналитики

Инструкция для **Google Sheets, Power BI, Roistat, МойСклад**. Механика выгружает наборы данных 1С во внешнюю систему аналитики по расписанию (по умолчанию — ежедневно в 06:00).

Направление — **только 1С → система аналитики**.

---

## Шаг 1. Запустить мастер

Каталог проектов → **«+ Добавить интеграцию»**. Шаги 1–2 — см. **[Мастер подключения](../02-Основы/Мастер-подключения.md)**.

**Шаг 3А** → категория **`analytics` (Аналитика)**.
**Шаг 3Б** → сервис: `google_sheets`, `powerbi`, `roistat` или `moysklad`.

---

## Шаг 2. Механики

![Шаг 3В: механика аналитики](../images/master-step3v-mech-analytics.png)

Механика одна — **«Аналитика»**.

**Шаг 3Г** — **★ Рекомендуемые**. **Шаг 4** — название проекта. **Шаг 5** — **«✓ Завершить и запустить»**.

---

## Шаг 3. Настроить выгрузку

Рабочий стол проекта → строка **«Аналитика»** → **⚙ Настройка**.

![Настройка аналитики](../images/analytics-setup.png)

### Расписание и поведение

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| **Время запуска ЦиклАналитики** | `06:00` | Когда запускается плановая выгрузка |
| **Режим (full / delta)** | `delta` | Вся история или только изменения |
| **Период delta (дней)** | `30` | Глубина для режима `delta` |
| **Размер чанка (строк)** | `5 000` | На сколько строк дробится большая выгрузка |
| **Уведомлять об успешной выгрузке** | `Да` | Требует механики [уведомлений](Уведомления-и-соцсети.md) |
| **Уведомлять об ошибках** | `Да` | То же |

### Параметры сервиса

На форме есть блок под каждый поддерживаемый сервис — заполняйте только свой.

**Google Sheets:**

| Поле | Назначение |
|---|---|
| **ID таблицы (Spreadsheet ID)** | Идентификатор Google-таблицы |
| **Лист: Продажи / Остатки / Заказы МП / Оплаты** | Имена листов под каждый набор данных |
| **Добавлять строку заголовков** | `Да` / `Нет` |
| **Очищать лист перед выгрузкой (full mode)** | `Да` / `Нет` |

**Power BI:** Dataset ID, Workspace ID, режим (`push` / `streaming`), размер батча.

**Roistat:** Project ID, передавать продажи (`sales`), передавать заказы МП (`orders_mp`), передавать UTM-метки из комментариев.

**МойСклад:** направление (`push` / `pull`), синхронизировать товары / остатки / цены.

**Иное (произвольный endpoint):** URL endpoint (POST), заголовки (JSON), сжимать payload (gzip).

Кнопки: **«Сохранить»**, **«Отмена»**, **«Тест подключения»**.

---

## Шаг 4. Рабочее место «Аналитика»

Рабочий стол → строка **«Аналитика»** → **▶ Рабочее место**.

![Рабочее место аналитики](../images/analytics-workplace.png)

### Фильтр

Поля **С** / **По** и **Набор** — период и набор данных для отображения истории.

### Ручной запуск

| Элемент | Назначение |
|---|---|
| **Набор данных** | Какой набор выгрузить |
| **Полная выгрузка (full)** | Выгрузить всё, а не дельту |
| **Запустить выгрузку** | Выгрузить выбранный набор |
| **Запустить все** | Выгрузить все наборы подряд |

### Текущий статус

**Цикл аналитики** (`Ожидание` / выполняется), **Последний запуск**, **Строк выгружено**.

Кнопки **«Обновить»** и **«Повторить»**, поле **«Статус»**.

### История выгрузок

| Колонка | Значение |
|---|---|
| **Время** | Время выгрузки |
| **Набор данных** | `sales`, `stock`, `orders_mp`, `payments` |
| **Режим** | `full` / `delta` |
| **Строк** | Сколько строк выгружено |
| **Чанков** | На сколько частей разбито |
| **Длит., с** | Длительность |
| **Статус** | `success` или ошибка |
| **Ошибка** | Текст ошибки |

Блок **«Детали ошибки»** и итоги: «Записей», «Успешно», «Ошибок».

---

## Наборы данных

| Набор | Что выгружает |
|---|---|
| `sales` | Продажи |
| `stock` | Остатки |
| `orders_mp` | Заказы маркетплейсов |
| `payments` | Оплаты |

---

## Различия по конфигурациям 1С

| Конфигурация | Особенности |
|---|---|
| **УТ 11** | Все наборы данных |
| **УНФ** | Все наборы данных |
| **КА 2 / ERP** | Все наборы. ⚠️ Все запросы фильтруются по организации проекта |
| **БП 3.0** | ⛔ Набор **`stock` недоступен**. Остальные наборы работают; продажи выгружаются без складской детализации |

---

## Проверка после настройки

1. **«Тест подключения»** в настройке.
2. Рабочее место → выбрать **Набор данных** → **«Запустить выгрузку»**.
3. В истории должна появиться строка со статусом **`success`** и ненулевым количеством строк.
4. Проверить, что данные дошли до целевой системы (лист Google Sheets, датасет Power BI и т. д.).

---

## Частые проблемы

| Симптом | Решение |
|---|---|
| История выгрузок пустая | Нажмите **«Обновить»**; проверьте фильтр **С / По** — по умолчанию показывается ограниченный период |
| Выгрузка со статусом ошибки | Откройте блок **«Детали ошибки»**; проверьте **«Тест подключения»** и параметры сервиса |
| Строк выгружено = 0 | В выбранном периоде нет данных. Попробуйте **«Полная выгрузка (full)»** |
| Набор `stock` не выгружается | В БП 3.0 он недоступен. В других конфигурациях проверьте настройку складов |
| Выгрузка идёт очень долго | Уменьшите **«Размер чанка (строк)»** либо сократите **«Период delta (дней)»** |
| Данные в Google Sheets дублируются | Включите **«Очищать лист перед выгрузкой (full mode)»** |
| Не приходят уведомления о результате | Механика [уведомлений](Уведомления-и-соцсети.md) не подключена отдельным проектом |
| Нужна выгрузка чаще раза в сутки | Измените **«Время запуска ЦиклАналитики»** или запускайте вручную кнопкой **«Запустить все»** |
