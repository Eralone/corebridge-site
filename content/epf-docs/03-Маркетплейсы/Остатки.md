# Как настроить выгрузку остатков

Механика отправляет остатки складов 1С на маркетплейс или сайт. Работает по расписанию (по умолчанию — каждые 5 минут).

**Это одна из двух механик, которые обязательно нужно настроить руками после создания проекта** (вторая — [сопоставление товаров](Каталог-и-сопоставление.md)). Без выбранных складов остатки не выгружаются вообще.

---

## Шаг 1. Открыть настройку

Рабочий стол проекта → строка **«Остатки»** → **⚙ Настройка**.

![Настройка синхронизации остатков](../images/stock-setup.png)

---

## Шаг 2. Выбрать склады (обязательно)

Верхний блок **«Склады»**.

Строка **«ДиагностикаЗагрузки»** показывает, сколько складов прочитано из базы: `✓ Загружено 27 складов из Справочник.Склады · кабинетов: 3`.

**Таблица складов:**

| Колонка | Значение |
|---|---|
| **Выбран** | `Да` / `Нет` — участвует ли склад в выгрузке |
| **Склад 1С** | Наименование склада |
| **Код 1С** | Идентификатор склада в базе |
| **ID склада МП** * | Идентификатор склада на стороне маркетплейса |
| **SKU на складе** | Сколько позиций числится на складе |

**Кнопки управления:**

| Кнопка | Действие |
|---|---|
| **✓ Выбрать строку** | Включить текущий склад |
| **□ Снять строку** | Выключить текущий склад |
| **✓ Выбрать все** | Включить все склады |
| **□ Снять все** | Выключить все |
| **↺ Обновить склады** | Перечитать список складов из базы |

Поле **«ИтогоSKU»** показывает суммарное количество позиций по выбранным складам.

> **Самая частая ошибка при внедрении** — пропустить этот шаг. Если ни один склад не выбран, экран «Управление товарами 1С» будет пустым, а на маркетплейс не уйдёт ничего. Для старта проще всего нажать **«✓ Выбрать все»**.

---

## Шаг 3. Параметры выгрузки

Блок **«Параметры выгрузки»**:

| Параметр | Что задаёт |
|---|---|
| **мин (5–60)** | Интервал выгрузки в минутах. По умолчанию `5` |
| **ПредупреждениеИнтервала** | Подсказка при слишком частом интервале |
| **Вычитать резервы из остатков** | Отправлять остаток за вычетом резерва. Включён по умолчанию — защищает от продажи зарезервированного товара |
| **шт.** | Страховой запас: сколько единиц не выгружать (буфер) |
| **Выгружать остатки сразу после проведения документа в 1С** | Дополнительно выгружать по факту движения, не дожидаясь интервала |

Блок **«Фильтрация товаров»**:

| Параметр | Что задаёт |
|---|---|
| **Не выгружать товары с нулевым остатком** | Включён по умолчанию — нулевые позиции не отправляются |

Нажмите **«Сохранить»**.

> Форма закрывается по кнопке «Сохранить». Если закрыть по «Отмена», выбор складов не сохранится.

---

## Шаг 4. Проверить выгрузку

Рабочий стол → строка **«Остатки»** → **▶ Рабочее место**.

Открывается общий экран хаба «Товары» — **«Управление товарами 1С»**.

![Управление товарами 1С](../images/goods1c-sync.png)

| Элемент | Назначение |
|---|---|
| **Кабинет** | Проект |
| **↺ Обновить товары** | Перечитать данные из 1С и с маркетплейса |
| **ВремяОбновления** | Когда данные были прочитаны |
| **Синхронизировать остатки ↑** | Отправить остатки на маркетплейс **сейчас** |
| **Синхронизировать цены ↑** | Отправить цены |
| **Синхронизировать резервы ↑** | Отправить резервы |
| **ВсегоПозиций / Расхождений** | Счётчики |
| **ИнфоМП** | Сводка: товаров, складов, сопоставлено, с данными МП |

**Таблица сравнения** — главный инструмент диагностики:

| Колонка | Значение |
|---|---|
| **Артикул МП** | Артикул на маркетплейсе (`—`, если товар не сопоставлен) |
| **Номенклатура 1С** | Позиция в базе |
| **Ост. 1С / Ост. МП / Δ ост** | Остаток в 1С, на маркетплейсе и разница |
| **Цена 1С / Цена МП / Δ цена** | То же по ценам |
| **Рез. 1С / Рез. МП / Δ рез** | То же по резервам |
| **Сопост.** | Признак сопоставления |

Ненулевая **Δ ост** означает, что данные разошлись — нажмите **«Синхронизировать остатки ↑»**.

---

## Как это работает

1. По расписанию (интервал из настройки) модуль читает остатки по **выбранным складам**.
2. Если включено «Вычитать резервы» — вычитает резерв, если задан страховой запас — вычитает и его.
3. Отбрасывает нулевые позиции, если включён соответствующий фильтр.
4. Отправляет остатки **только по сопоставленным товарам**.

Несопоставленный товар в выгрузку не попадает — в таблице он виден со значением `—` в колонке «Артикул МП».

---

## Различия по конфигурациям 1С

| Конфигурация | Как читаются остатки |
|---|---|
| **УТ 11** | Регистр товаров на складах, фильтр по выбранным складам |
| **УНФ** | Регистр запасов |
| **КА 2 / ERP** | Регистр товаров на складах, дополнительно фильтруется по организации проекта |
| **БП 3.0** | ⚠️ Из бухгалтерского учёта по счёту товаров. **Складской детализации нет** — выгружается общий остаток, выбор складов не влияет на результат |

## Частые проблемы

| Симптом | Решение |
|---|---|
| Экран «Управление товарами 1С» пустой | Не выбраны склады. **⚙ Настройка** → **✓ Выбрать все** → **Сохранить** |
| Остатки не уходят на маркетплейс | 1) Не выбраны склады. 2) Товары не сопоставлены — колонка «Артикул МП» = `—` |
| В таблице все строки с `—` в «Артикул МП» | Не выполнено сопоставление. См. [Каталог и сопоставление](Каталог-и-сопоставление.md) |
| Остаток на маркетплейсе меньше, чем в 1С | Ожидаемо, если включено «Вычитать резервы из остатков» или задан страховой запас |
| Товар кончился, но остаётся на витрине | Включён фильтр «Не выгружать товары с нулевым остатком» — нулевые позиции не отправляются, и маркетплейс не узнаёт об обнулении. Снимите флажок, если нужно явно обнулять остатки |
| Список складов не совпадает с базой | **«↺ Обновить склады»** на форме настройки |
| Слишком высокий расход операций | Увеличьте интервал в поле «мин (5–60)», либо на Шаге 3Г мастера уменьшите частоту строки выгрузки остатков |
| В БП 3.0 остатки без разбивки по складам | Ожидаемо — см. таблицу выше |
