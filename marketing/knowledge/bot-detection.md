# Отсев роботов: что проверено на своих данных

Одна тема, три проверки, все на живых логах corebridge.ru.

## Робот проходит любую проверку «похож ли на браузер»

**24.08.** Googlebot ходит под UA мобильного Chrome и грузит `site.css`.
Безголовый Chrome выполняет наш счётчик и присылает события: семь страниц
в одну секунду, окно ровно 1280x720, на каждой странице новый `visitor_id`
(cookie он не хранит). Счётчик поймал «iPhone» с окном 1920x1080.

**07.09.** Сканеры подделывают `Referer`: `google.com`, `bing.com`, IP нашего
же сервера. За неделю так прошли 36 сканеров, визиты показывали 79 вместо 26.

## Что работает

| Признак | Надёжность |
|---|---|
| Наша метка `utm_campaign` в ссылке | высокая: имя кампании неоткуда взять |
| Поведение (страниц в единицу времени) | средняя |
| Запрос к путям сканеров | высокая, но ловит не всех |
| Загрузка `site.css` | низкая: роботы грузят, люди кешируют |
| Внешний `Referer` | **никакая: подделывается тривиально** |
| Исполнение JavaScript | низкая: безголовый браузер исполняет |

## Правило

Проверку «качал ли site.css» обходит только метка, ничто другое.
Список путей сканеров общий у сторожа и у отсева (`mktlib.PROBE_RE`) —
две отдельные копии успели разойтись и пропускали `/frontend/.env`.

## Чего это стоило

Три пересчёта одних и тех же недель августа. Ряд визитов до 24.08
восстановить нечем: логи nginx живут 14 суток.

Вывод на будущее: не наращивать эвристики по логам дальше. Считать главную
метрику по меткам, логи держать для мониторинга ошибок и обхода роботами.
